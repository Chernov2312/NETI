# NETI

NETI — каталог студенческих проектов с оценками, тегами и галереями. Посетители могут отправить обращение через форму обратной связи, а сотрудники обрабатывают обращения и жалобы в Django Admin. Проект использует Django 5.2, Python 3.13 и PostgreSQL 15.

## Локальный запуск

Из корня репозитория в PowerShell установите зависимости и создайте `.env` из примера.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements/test.txt
Copy-Item .env.example .env
```

Задайте собственные значения `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` в `.env`. Для уже установленного PostgreSQL укажите доступные базу и пользователя в `POSTGRES_DB` и `POSTGRES_USER`. Для локальных тестов пользователь PostgreSQL должен иметь право `CREATEDB`.

```powershell
docker compose up -d --wait postgres
python neti\manage.py migrate
python neti\manage.py runserver
```

Для запуска приложения и базы в Docker используйте `docker compose up --build -d`. Контейнер приложения применяет миграции при запуске. В обоих вариантах приложение доступно на `http://127.0.0.1:8000`. Compose использует те же значения ключа, DEBUG и разрешённых хостов из `.env`. Файлы проекта сохраняются в `DJANGO_MEDIA_ROOT` на хосте, по умолчанию в `neti/media`.

## Перенос данных из SQLite

Для новой базы достаточно `migrate`. Если в SQLite уже есть данные, остановите запись в приложение, сохраните копии SQLite и каталога медиа. Укажите путь к копии базы в `DJANGO_SQLITE_PATH`, примените к ней текущие миграции и выгрузите данные. Используйте пустую целевую базу PostgreSQL.

```powershell
$netiDump = Join-Path $env:TEMP 'neti-sqlite-data.json'
$env:DJANGO_DB_ENGINE = 'sqlite'
$env:DJANGO_SQLITE_PATH = 'C:\path\to\db-copy.sqlite3'
python neti\manage.py migrate
python neti\manage.py dumpdata auth.group user project feedback admin --all --natural-foreign --output $netiDump

$env:DJANGO_DB_ENGINE = 'postgresql'
python neti\manage.py migrate
python neti\manage.py loaddata $netiDump
```

После переноса проверьте вход пользователей, проекты и доступность файлов. Укажите прежний каталог медиа или скопируйте его содержимое в новый с сохранением путей. Сессии и кэш миниатюр будут созданы заново. Храните экспорт вместе с резервной копией базы, так как он содержит пользовательские данные и хеши паролей.

## Каталог

Регистрация открыта. Новые аккаунты получают роль «Студент». Любой вошедший пользователь может публиковать проекты, открывать список своих проектов и изменять выставленные оценки. Редактировать и удалять проект могут его владелец, модераторы и суперпользователи. Теги создаются в Django Admin, выбираются в форме проекта и используются для фильтрации каталога.

Каталог поддерживает поиск по части названия и выводит по 12 проектов на страницу, сначала недавно обновлённые. Запрос и выбранный тег сохраняются при переходе между страницами. Для PostgreSQL миграция добавляет триграммный GIN-индекс по названию и индекс для порядка выдачи. Если учётная запись для миграций не может создавать расширения, заранее включите `pg_trgm` в целевой базе.

Форма проекта принимает PDF до 10 МБ и изображения JPEG, PNG и WebP до 5 МБ и 16 мегапикселей каждое. Главное изображение необязательно. В галерею можно добавить до 10 фотографий, а при редактировании можно удалить выбранные фотографии или заменить главное изображение.

## Восстановление пароля

На странице входа выберите «Забыли пароль?» и укажите email аккаунта. Django отправит одноразовую ссылку для установки нового пароля.

При `DJANGO_DEBUG=True` письмо выводится в консоль приложения, для Docker используйте `docker compose logs neti`. При `DJANGO_DEBUG=False` заполните SMTP-параметры из `.env.example` и задайте `DJANGO_DEFAULT_FROM_EMAIL`. Выберите TLS или SSL в соответствии с настройками SMTP-сервера. Проверьте отправку через публичный HTTPS-адрес, чтобы в письме была ссылка с правильным доменом и протоколом.

## Модерация

Суперпользователь назначает или снимает роль «Модератор» в разделе «Пользователи» в Django Admin. Для работы с жалобами модератору достаточно этой роли.

Вошедший пользователь может нажать «Пожаловаться» на странице проекта и указать причину. Модераторы и суперпользователи открывают очередь через пункт «Жалобы» в меню, переходят к проекту и отмечают жалобу как рассмотренную. Пока жалоба в очереди, тот же пользователь не может отправить повторную жалобу на тот же проект.

## Обратная связь и администрирование

Форма «Обратная связь» доступна в подвале сайта и по адресу `/feedback/`. Посетитель указывает имя, email и сообщение. Для вошедшего пользователя контактные поля заполняются автоматически и доступны для редактирования.

Панель управления находится по адресу `/admin/`. Создайте суперпользователя командой, соответствующей способу запуска.

```powershell
python neti\manage.py createsuperuser
docker compose exec neti python neti/manage.py createsuperuser
```

- В разделе **«Обратная связь» → «Обращения»** сотрудники с правом редактирования меняют статус обращения и оставляют внутреннюю заметку. Для ответа отправителю используйте ссылку в карточке обращения, которая открывает почтовую программу.
- В разделе **«Каталог проектов»** доступны поиск, фильтры, миниатюры и редактирование галереи. В списке жалоб можно отметить несколько жалоб как рассмотренные. Панель сохраняет сотрудника и дату первого рассмотрения.
- Раздел **«Пользователи»** доступен суперпользователю. Там можно назначить роль модератора и выдать сотруднику права на разделы панели.

## Данные для демонстрации

Загрузите `demo/neti-demo.json` в пустую тестовую базу после миграций командой `python neti/manage.py loaddata demo/neti-demo.json`. Для работы PDF и галереи скопируйте `demo/files/neti-demo` в каталог `DJANGO_MEDIA_ROOT`. У аккаунтов `demo_student` и `demo_moderator` общий демонстрационный пароль `DemoNeti-Only!26`.

## Проверки и доставка

Команда `test` из корня репозитория запускает проверки Django. Для локального запуска и CI используйте PostgreSQL. SQLite доступна для переноса старых данных и отдельных проверок.

```powershell
python neti\manage.py check
python neti\manage.py makemigrations --check --dry-run
python neti\manage.py test
```

Для браузерных тестов с запущенной PostgreSQL выполните:

```powershell
python -m pip install -r requirements/e2e.txt
python -m playwright install --only-shell chromium
python neti\manage.py test project.e2e_tests
```

Django создаёт отдельную тестовую базу, загружает `demo/neti-demo.json` и удаляет базу после прогона. Chromium проверяет регистрацию, редактирование проекта и вложения, фильтрацию и оценки, обработку жалоб, сброс пароля и отправку обращения через форму обратной связи.

GitHub Actions запускает проверки Django и браузерные тесты на PostgreSQL, собирает production-образ и проверяет HTTP-ответы каталога и статики. После успешных проверок на `master` workflow публикует в GHCR теги `latest` и `sha-<commit>`.

При развёртывании используйте тот же образ для команды `python neti/manage.py migrate --noinput`, затем запустите Gunicorn штатной командой образа. Задайте `DJANGO_DEBUG=False`, ключ, хосты и реквизиты PostgreSQL. Статика включена в образ. Для пользовательских файлов подключите постоянное хранилище к `DJANGO_MEDIA_ROOT` и настройте раздачу изображений по `/media/` через веб-сервер.
